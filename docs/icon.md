# ADAPT icon

A single geometric capital **A**. The left stroke is solid green; across the
crossbar and the right stroke it thins through a few slanted slices into a
wireframe drawing with a centre line, hidden edges, four anchor nodes, two
dimension lines and one registration mark. Greens, white and gray come from
the terminal identity. There is no wordmark and no background.

**Status:** this is a design proposal shipped as a local asset pack. Nothing
has been installed into any system, terminal profile, shortcut or executable.
The native receiver's `resource_stamp` still embeds its own older icon and is
unchanged.

## Files

All in `docs/assets/icon/`, generated by `scripts/build_icon.py`:

| File | Use |
| --- | --- |
| `adapt.svg` | Master vector, transparent, 1024 viewBox, no fonts, rasters or external references |
| `adapt.png` | 1024 px transparent raster of the master |
| `adapt-256.png`, `adapt-128.png`, `adapt-64.png`, `adapt-48.png`, `adapt-32.png`, `adapt-16.png` | Size exports |
| `adapt.ico` | Windows icon with 16, 24, 32, 48, 64, 128 and 256 px entries |
| `adapt-preview.png` | Presentation tile on a dark background (for docs, not an app icon) |
| `manifest.json` | Byte size and SHA-256 of each file |

Detail is reduced as the size drops, on the same letter geometry:

| Sizes | Drawing |
| --- | --- |
| 1024, 256 | Full drawing |
| 128, 64, 48 | Solid left, two slices, heavier wireframe, no drafting marks |
| 32, 24 | Solid left, heavy outline with a light green tint |
| 16 | Two-tone solid A (bright left, deep green right) |

## Rebuild and verify

```sh
python scripts/build_icon.py          # write the assets and manifest
python scripts/build_icon.py --check  # regenerate in memory, compare with disk
```

Needs only Pillow. The SVG and the rasters are written from one shape list, so
they cannot drift apart. Output is byte-stable for a given Pillow build; a
different Pillow or zlib version can compress the PNGs differently, in which
case rebuild and commit the new manifest.

## Where an icon can be used

The paths below are placeholders. Replace them with wherever you keep the file.

**Windows shortcut.** Shortcut properties, *Change Icon*, pick `adapt.ico`; or
from PowerShell:

```powershell
$s = (New-Object -ComObject WScript.Shell).CreateShortcut("<path>\ADAPT.lnk")
$s.TargetPath = "<path-to-launcher>"
$s.IconLocation = "<path>\adapt.ico"
$s.Save()
```

**Windows installer or native executable.** Point the installer's icon setting,
or the resource step of a native build, at `adapt.ico`. A plain Python console
entry point (the `adapt` script that `pip` or `uv` creates) does not carry an
icon of its own, so this applies only to a real installer or compiled binary.

**Windows Terminal profile.** In `settings.json`:

```json
{ "name": "ADAPT", "commandline": "<command>", "icon": "<path>\\adapt.ico" }
```

A PNG path such as `adapt-32.png` also works there.

**Linux desktop entry.** In a `.desktop` file:

```ini
[Desktop Entry]
Type=Application
Name=ADAPT
Exec=<command>
Terminal=true
Icon=<path>/adapt.svg
```

`Icon=` also accepts a PNG path, or a bare theme name if the PNGs are installed
into an icon theme directory.

**Repository, docs and favicons.** Use `adapt.svg` in Markdown or HTML, with
`adapt-32.png` or `adapt.ico` as the favicon fallback:

```html
<link rel="icon" type="image/svg+xml" href="<path>/adapt.svg">
<link rel="alternate icon" href="<path>/adapt.ico">
```

**T3 project association.** Where the T3 client lets a project pick an icon
file, use `adapt.svg` or `adapt-256.png`.

## What it cannot do

Terminal output has no portable application icon. When ADAPT runs in a shell,
the window, tab and taskbar icon belong to the terminal that launched it, which
is why the terminal-profile and shortcut routes above are the ones to use.
