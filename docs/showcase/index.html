Generated. Source-derived illustration with synthetic values. Nothing was run on a host, network or device.

Highlights (press one to light its lines)

  • Profile values are asserted against dev_options._PROFILE_VALUES at build time. ADAPT writes no other keys and no properties.
  • A serial is required and physical identity is read separately; a USB serial or wireless endpoint is never treated as identity.
  • The recovery file is created exclusively with the originals before the first device write.
  • Restore refuses to overwrite a value changed by something else and retains the record (docs/dev-options.md).

Highlights (press one to light its lines)

  • pc-start refuses without --yes, a shared-ADB preflight and an exclusively created snapshot bound to the device identity.

What this showcase does not claim

  • Generated views show the shape of ADAPT output, not results. No host check, device, network or pairing ran, and every serial, package and peer name is a placeholder.
  • There are no Android screenshots here. The rendered capture image is drawn by scripts/build_showcase.py; it is not a Windows Terminal screenshot.
  • Samsung DeX for PC is experimental. Fifteen native unit tests exist in source, one Android 13 reconnect was observed historically, and that is not support for every device or Android version. Receiver launch is not a shipped CLI backend.
  • Direct Tailnet ADB is not confirmed end to end because the current live verifier has a gap; view 6 shows the documented stages only.
  • Android 10 to 17 rows are planning data from the CLI's own matrix, not certification on every OEM build.
